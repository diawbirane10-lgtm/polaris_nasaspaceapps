# NASA Space Apps Evidence-first Pitch

## Role
Project-specific POLARIS 2026 agent workflow. Apply its checks to source code and evidence; instructions alone are not a pass.

## Steps
1. In 20 seconds, state the challenge problem: lunar site/date change affects illumination and Earth visibility.
2. Demonstrate user action: choose site and date, run calculation, compare a delayed scenario, explain the tradeoff.
3. Every numeric claim points to actual output, traceable NASA source and stated model limitations.
4. State what is novel versus QuickMap, Moon Trek, and existing GitHub implementations: explainable re-planning and coupled energy scenario, not a fictional spaceflight certification.
5. Keep a minimal fallback demo ready with explicitly labeled recorded, real-data results (if independently validated).
6. Include GitHub URL, public demo if deployed, citations, collaborators, third-party resources and AI-use disclosure.

## Exit criteria
- Concrete file/test/evidence changes, or explicitly documented blocked step.
- Risks and unverified claims disclosed.
- No installation script, authentication change or remote action is implied by reading this file.
